实际 API 预检：读取文件清单与创建“播客资料库”均返回 99991672，缺少应用身份对应权限，没有创建出文件夹。

同日用用户原话“告诉我过去一周更新了什么播客”实测：模型调用 `recent_updates(days=7, show="")`，检查全部 14 个订阅源，取得 26 期、0 个来源失败，输出了 26 条带日期和原始标题的目录。没有读取文字稿目录。实测发现并修复了两类问题：把“全部追踪节目”误作节目名的工具参数歧义，以及模型改写元数据时错误计数。现在参数未匹配时返回可修正反馈，更新目录由检索结果直接渲染；模型仍自主选择工具，内容分析仍须引用正文。`scripts/smoke_recent_updates.py` 会校验全部来源被覆盖、七天窗口未丢失、返回条目未被省略，并禁止以文字稿库存替代更新检索。

目标是一个云端常驻的独立研究 Agent，飞书负责接收消息和交付，模型负责自主选择工具、观察结果、补充检索并回答。采用 OpenAI Agents SDK，而不是 Codex SDK。对比 LangGraph 后选择前者：当前需求是单个研究 Agent 的工具循环，现有服务是 Python + OpenAI；无需先设计一张固定业务流程图。队列只承担防丢、重试和消息交付，不参与问题分类或研究决策。

选型依据：[Agents SDK](https://developers.openai.com/api/docs/guides/agents/sdk)、[运行循环与会话策略](https://developers.openai.com/api/docs/guides/agents/running-agents)、[LangGraph 官方概览](https://docs.langchain.com/oss/python/langgraph/overview)。框架本身不会让证据不全的回答变正确，能力仍由工具、资料覆盖和验收共同决定。

## 运行路径

飞书消息 → 访问白名单及会话历史 → SDK Agent/Runner → 自主检索、读全文、查询来源 → 引用校验 → 飞书回复。

入口和出口的持久队列仅是上述过程的可靠交付层。`agent_runtime.py` 封装 SDK；`research_agent.py` 提供业务工具和证据校验。框架负责每一步的模型与工具调度，不再经过旧版六类意图分类器。

每日采集及单期分析继续使用完整文字稿门槛。独立归档 worker 每分钟扫描已核验文字稿，在指定飞书文件夹创建可读文档，分批写入并回读全部段落后才标记完成。失败续传，不覆盖人工编辑，已移走或删除的完成文档不自动复活。

归档逐篇隔离失败：一篇被手工修改或写入失败，不阻塞后续节目。问答读取时，单篇文档或子文件夹失败会明确披露，其他可读文档仍可检索；资料库根目录不可读则停止，不能用旧缓存冒充当前资料。

模型可调用的工具：读取真实追踪列表；按名字找 RSS；验证新增候选；经下一条用户消息确认后保存追踪；查询过去 1–31 天的官方 RSS 更新；列出资料库文档；检索正文；继续阅读前后文；分析用户提供或本轮 RSS 检索实际返回的单期链接。新节目可以查到后直接调用分析工具，不要求用户重复复制链接。工具没有 shell、任意 API、跨文件夹搜索或自由发送消息权限。

新增来源保存在持久 SQLite 中，日常发现流程读取同一份配置，部署与重启不会丢失。新增影响团队共享列表，因此先展示准确节目与 RSS，再由用户回复“确认添加”。同名来源应先澄清。当前自动发现面向播客 RSS；未提供 RSS 的视频源查询会明确报告未覆盖，不声称没有更新。

资料库每次问答重新枚举文件夹及子目录，并读取当前新版文档正文。手工加入的文档也进入检索，移动、删除和无权限文档不使用旧缓存。正文检索为词项召回，模型可用中英文关键词反复搜索与分页读正文，不是向量检索。图片、附件和非 docx 文件不在正文读取范围，须披露。会话按私聊用户、群及用户、话题隔离；不会自动导入个人电脑资料或其他群历史。

## 最小权限与启用

在飞书应用后台开通应用身份权限并发布生效：

- `space:folder:create`：创建归档文件夹。
- `space:document:retrieve`：列出指定文件夹文档。
- `docx:document`：创建、读取及写入新版文档。
- `docs:permission.member:create`：给指定用户或团队群授予资料库权限。

这些是应用 API 权限，文件夹自身的资源权限仍须设置。不要为此开启整个租户的无关数据权限，不要公开分享文件夹。用户应有文件夹管理员权限；团队群仅按明确授权范围分享。模型 API 与飞书 Secret 仍只存在云端环境变量。

设置 `.env.example` 中的 `NEWS_OFFICER_LIBRARY_FOLDER` 和明确的 `NEWS_OFFICER_RESEARCH_USERS` / `NEWS_OFFICER_RESEARCH_CHATS`。访问白名单不能自动等同于日报订阅，否则任意订阅者可读取团队资料。权限与云端验收通过后再设置 `NEWS_OFFICER_RESEARCH_AGENT=true`。该模式下普通自然语言由新 Agent 接管，旧路由仅用于回滚。

问答会把用户问题、当前会话有限历史与相关文档片段发送至现有配置的 OpenAI API；`store=false`，关闭 SDK 远端 tracing，本地持久状态在 `/data`。这不等于数据不经过模型服务商。循环最多 16 次模型调用、32 次工具执行，每次最多 2200 输出 token；所有证据修正共用同一预算。配置模型保持不变。

会话采用 SDK 支持的应用管理 replay 策略，不同时混用服务端 conversation ID 或 previous response ID。SQLite 存储已校验的问题/答案，与消息去重原子提交；后续保留最多 20 个完整轮次、32,000 字符。不会重放旧工具证据，内容追问须重新查询本轮资料。不是无限记忆，也不宣称进程崩溃后能恢复到模型推理中途。

每次工具执行的名称、成功/失败及耗时保存在 `research_steps`；不存密钥、工具参数或全文到遥测。工具异常反馈给 Agent 以便更换查询或解释限制，未通过引文校验的结论不发送。SDK 输出结构约束不等于语义事实校验，两层需分别验收。

## 必须完成的上线验收

1. 创建真实“播客资料库”文件夹，授予用户访问权限，存档现有节目并逐段回读验证。
2. 飞书私聊及指定团队群能问“在监听哪些播客”，答复与实际采集源一致。
3. 按名称找到一个真实 RSS，用户确认后保存；重启后仍存在，实际每日发现会检查它。
4. 查询过去七天更新时实际读取来源并保留日期条件；不能只列出已归档节目。
5. 用中文问英文文字稿中的特定观点，能自主搜索、阅读并返回正确文档链接；跨文档比较不混淆说话人。
6. 修改、加入和移走文件夹文档后，新一轮问答体现变化；无法读取时明确报告。
7. 群/私聊上下文不串线；无白名单者无法触发资料库读取；发送重试不重复运行研究。

离线测试不能替代这些云端验收。未通过时不得称为已上线。
